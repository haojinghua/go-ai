### 1.2 前端交互逻辑要点（代码审查项，读 index.html）

- **双 Tab 状态隔离**：对弈/分析共用同一 canvas（`currentTab` 切换绘制 `board`/`analyzeBoard`）；切 Tab 时 `analyzeResults` 被清空、对弈推荐不清空。
- **对弈流程**：`newGame()` → 若玩家选白，先 `/api/ai_move` 让 AI 先手；玩家点棋盘 → 本地落子+提子 → `/api/play` → AI 落子回填 → 自动 `fetchPlayRecommendations()`（max_visits=800）。
- **悔棋重放**：`undoMove()` 从 `moveHistory` 字符串（`"B: D4"` 格式）重放重建棋盘——依赖字符串解析，格式改动是高风险区。
- **分析模式浏览**：`analyzeBaseBoard`（截图识别的底板）+ `analyzeMoveHistory`（手动落子），`analyzeMoveIndex` 控制前后浏览；中途回退后再落子会**截断**后续历史。
- **提子一致性**：前端 `removeCaptures` 与后端 KataGo 各自维护提子，两边不一致会导致棋盘错乱（回归时重点看对弈多手后棋面）。
- **PV 悬停**：鼠标悬停推荐点显示前 10 手 PV 半透明变化图；`mouseleave` 清除。
- **导出 SGF**：仅导出手数序列，pass 为 `B[]`/`W[]`，无提子/摆子信息。
- **已知前端缺陷**（回归时记录，不要求修复）：`undoMove` 中 `parts = saved[i].split(': ')` 解析 "Pass"/"Resign" 时 `gtpToBoard` 返回 null 被跳过，重放不含 pass。

## 2. 十三个待开发功能验收标准

> 通用要求（所有功能）：不破坏现有冒烟回归；服务崩溃自动重启逻辑不受影响；API 错误必须返回 JSON（不能裸 500 HTML）；前端任何新按钮在等待期间禁用防重复提交。

### F1. SGF 棋谱导入

- **功能描述**：分析模式载入 .sgf 文件，后端解析主线着法，前端重建局面并可前后浏览。
- **后端验收点**：
  - 新端点（如 `/api/import_sgf`）接收 `{sgf_text}` 或文件上传，返回 `{status:"ok", board_size, komi, moves:[[color,move],...], setup_stones, game_info{PB,PW,DT,...}}`。
  - 必须正确解析：`SZ[]`（9/13/19）、`KM[]`、`AB[]/AW[]` 摆子、主线 `;B[dd];W[qq]`（含多变体时只取主线）、pass（`B[]` 或 `B[tt]` 19 路）、`RE`、`PB/PW`。
  - 边界：空文件、非 SGF 文本、截断括号、SZ 非 9/13/19、含注释 `C[]`/标号 `LB[]` 的复杂 SGF → 均返回结构化错误，服务不 500、不崩。
- **前端验收点**：载入后棋盘尺寸随 SZ 切换；AB/AW 摆子直接显示；手数显示 `n/total`；⬅/➡ 浏览正常；载入后可点「AI 分析」且用 move_history（而非 initialStones）路径。
- **必测边界用例**：带提子的棋谱（提子后局面正确）、纯 pass 棋谱、带 AB 摆子的死活题 SGF、自己导出的 SGF 能重新导入（往返一致）。

### F2. 对局保存与载入

- **功能描述**：localStorage 保存对局进度，历史对局列表，载入续下。
- **后端验收点**：纯前端功能（localStorage），无新端点；但**载入续下时必须重新向后端 `/api/new_game` 同步 board_size/komi/max_visits 并重放 move_history 到 GTP 引擎**（可复用 /api/play 或新增重放端点），否则 AI 状态与前端不同步。
- **前端验收点**：保存包含 board_size、komi、playerColor、moveHistory、时间戳；列表显示日期+手数；载入后棋盘、手数、轮到谁走全部正确；续下一手后 AI 正常应答且提子正确；localStorage 满/损坏（JSON parse 失败）时优雅降级不白屏。
- **必测边界用例**：9 路和 19 路各存一局交替载入；载入含 pass 的对局；载入后立即悔棋；同一局保存两次不产生重复条目（或明确允许）。

### F3. 局面分享（已移除，存档）

> 2026-09-27 功能精简：复制局面按钮已从分析页移除，本节仅作历史存档。SGF 导入/导出（对弈页导出棋谱 + 导入 SGF）仍保留。
- **功能描述**：复制当前局面为 SGF 文本或含局面数据的 URL，能被程序自己重新导入还原。
- **后端验收点**：导出的 SGF/URL 无需后端（前端生成）；导入侧复用 F1 的解析端点——**验收必须做闭环测试**：导出 → 导入 → 棋面逐子一致。
- **前端验收点**：URL 形式（如 `?sgf=...` 或压缩参数）在页面加载时自动检测并还原；复制到剪贴板有成功提示；URL 超长（300 手 19 路）时仍可用或提示改用 SGF 文本。
- **必测边界用例**：空局面导出；含提子的局面导出再导入（提子信息必须保留——SGF 需含 `AB/AW` 或完整手数）；分享 URL 在隐身窗口打开。

### F4. 棋谱文本解析（已移除，存档）

> 2026-09-27 功能精简：粘贴棋谱文本载入入口及 `/api/parse_moves_text` 端点已删除，本节仅作历史存档。

- **功能描述**：粘贴 GTP 坐标序列（"B D4, W Q16" 或 "D4 Q16 dc..."）直接还原局面。
- **后端验收点**：新端点（如 `/api/parse_moves`）接收 `{text, board_size}`，返回 `{status:"ok", moves, board, next_player}` 或结构化错误。
  - 支持格式：①带颜色前缀（B D4, W Q16）；②纯坐标交替（D4 Q16 D3）；③大小写混合；④换行/逗号/分号分隔；⑤ pass 字样。
  - 边界：非法坐标（Z20、D25）、9 路棋盘上的 Q16、奇数个纯坐标、空文本、颜色连续两次相同（B D4 B Q5）→ 报错或按规则处理，必须明确文档化，不能崩溃。
- **前端验收点**：粘贴入口在分析 tab；解析后棋盘即时重建、手数编号正确、next_player 自动推断；错误信息具体指出第几个 token 有问题。
- **必测边界用例**：仅一手；100+ 手长序列；含 pass 的序列；9 路/19 路同一文本分别解析。

### F5. 全局胜率曲线图

- **功能描述**：对整局批量分析（KataGo analyzeTurns），绘制手数-胜率/目差折线图，点击曲线跳转局面。
- **后端验收点**：新端点（如 `/api/analyze_game`）接收 move_history + maxVisits，内部用 `analyzeTurns: [1..N]` **一次查询**（不是 N 次查询，验收时看耗时：50 手棋 maxVisits=100 应在 60s 内）；返回 `{status:"ok", points[{turn, winrate, scoreLead, best_move, ...}]}`；winrate 统一视角（建议黑棋视角，文档写明）。
- **前端验收点**：折线图有坐标轴/手数刻度；胜率与目差可切换或双轴；hover 显示手数+数值；**点击某一点棋盘跳到该手前后局面**；分析期间有进度提示且按钮禁用。
- **必测边界用例**：2 手极短对局；含 pass 的对局（turn 对齐不错位）；中途取消（可选）；分析时切走再切回 Tab 状态不丢。

### F6. 全自动整局复盘报告（已移除，存档）

> 2026-09-27 功能精简：复盘报告按钮、`/api/review_game` 端点已删除，本节仅作历史存档。

- **功能描述**：逐手评级（好手/疑问手/失误手），棋盘标注 + 总结报告。
- **后端验收点**：基于 F5 的批量分析结果计算逐手 ΔWinrate/ΔScore；返回每手 `{move, rating(good/doubtful/bad), delta, best_move_alternative}`；评级阈值需文档化（如 ΔWR ≤2% 好手、2-8% 疑问手、>8% 失误手）；报告含统计摘要（双方失误数、最大失误手）。
- **前端验收点**：棋盘上按评级标色（好/疑/失三种标记，最后一手圈样式不冲突）；报告列表可点击跳转对应手；总结区显示双方数据；pass 手的处理明确（通常不评级或标注）。
- **必测边界用例**：全好手的短对局（AI 自弈 20 手）；一手大恶手（人为构造）必须被识别为 bad；复盘过程中切 Tab；复盘完再点分析不互相污染。

- **必测边界用例**：试下非法点（已有子/自杀点）；试下后立即退出再正式落子（状态无残留）；在截图识别的 baseBoard 上试下。

### F10. 死活与局部提示

- **功能描述**：识别局部死活/官子机会并提醒。
- **后端验收点**：可基于 ownership/moveInfos 数据派生（如某块棋 ownership 接近 0 或翻转），或独立分析调用；返回 `{alerts[{type: "dead_group"/"endgame", stones, suggestion}]}`；误报率需人工抽检 10 个局面 ≥ 8 个合理。
- **前端验收点**：提示不打断操作（toast/侧栏）；点击提示定位到相关棋子（高亮）；可关闭单条提示。
- **必测边界用例**：明确的死棋局面（构造一块无两眼的棋）必须识别；活棋不误报；空盘不报；官子阶段（对局后期）给出至少 1 个合理官子点。

### F11. LLM 自然语言讲解

- **功能描述**：把 KataGo 分析结果交给 LLM 生成人话讲解。
- **后端验收点**：新端点接收分析数据（胜率、推荐、ownership 等），调用 LLM（本地或配置的 API）；**LLM 不可用时降级**为模板化文案而不是报错；超时（建议 30s）与 JSON 解析失败有兜底；响应 `{status:"ok", commentary}`。
- **前端验收点**：讲解显示在分析结果下方；生成中有 loading；可重新生成；讲解内容与当前局面/行棋方一致（不能张冠李戴说成另一方）。
- **必测边界用例**：LLM API key 缺失/断网（降级路径）；空棋盘请求讲解；超长对局数据（token 截断策略）。

### F12. 棋力评估与成长曲线

- **功能描述**：基于失误统计估算棋力，长期保存画成长曲线。
- **后端验收点**：依赖 F6 复盘数据；估算公式需文档化；保存使用 localStorage 或本地文件（新增持久化需防并发写坏）；返回 `{rating, history[{date, rating}]}`。
- **前端验收点**：评估结果含置信说明（样本量少时提示不准）；成长曲线有日期轴；数据可导出/清空；单次对局后评估增量更新。
- **必测边界用例**：首次使用（无历史）；同一天多局（聚合或并列显示，明确行为）；人为清空 localStorage 后曲线重置。

### F13. 错手集锦（错题本）

- **功能描述**：复盘大失误入库，生成重测练习。
- **后端验收点**：错题存储（localStorage/本地文件）；入库数据需自包含（局面 stones、错手、正解、日期），重测时不依赖原对局；查询端点分页/列表。
- **前端验收点**：复盘时一键入库（默认阈值如 ΔWR>8% 自动标记，可手动加入）；错题本列表（日期、局面缩略信息）；重测模式：摆出错误局面，用户下正解，AI 判定对错并给反馈；答对可标记已掌握。
- **必测边界用例**：同一失误重复入库去重；错题含提子局面正确还原；重测答错给正确答案展示；清空功能二次确认。

## 4. 附：测试工程师对现有代码的隐患观察（基线版）

1. **无请求并发保护**：ThreadingHTTPServer 并发请求 GTP 引擎时虽有 `engine.lock`，但 `/api/play` 在锁外先后调用 `play`+`genmove`，两个并发 `/api/play` 可能交错，导致引擎与前端棋面错乱。
2. **`/api/new_game` 不校验 board_size**：任意值（如 12、0）直接透传给 KataGo，可能引发引擎错误响应甚至进程退出。
3. **`/api/undo` 固定撤两手且吞错误**：空棋盘 undo 仍返回 ok；玩家是白棋且只有 AI 一手时，撤两手会失败但前端仍回滚本地历史，造成前后端不同步。
4. **`handle_pass` 中 genmove 失败时 ai_move 为 None 仍返回 200 ok**，前端 `data.ai_move` 判断后静默，状态栏可能停留在"AI 思考中"。
5. **分析引擎读 stdout 单行**：若 KataGo 输出多行（警告+结果），`readline` 只取第一行会 json 解析失败返回 error；`max_time` 兜底目前靠公式，弱网/慢机上 30s 超时可能不够（冒烟脚本需容忍）。
6. **前端 undo 重放依赖 `"B: D4"` 字符串 split**：任何改动 moveHistory 格式的新功能（F1/F2/F4/F13 都会动它）都必须同步回归对弈悔棋。
